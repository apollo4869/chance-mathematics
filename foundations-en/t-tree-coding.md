# T-TREE-CODING: Finite Plane Trees and Three Invertible Path Encodings

This companion proves the discrete coding results used in [Chapter 52](../chapters/52-discrete-trees.md#trees-addresses). Every edge has length one and every tree contains its root. The bijections concern finite trees; they are not asserted for arbitrary infinite trees or continuous real trees.

## 1. Addresses, ancestors, and a measurable state space

<a id="coding-addresses"></a>

\[ \mathcal U=\bigcup_{h\ge0}\mathbb N_+^h,\qquad \mathbb N_+^0=\{\varnothing\}. \]

Concatenation joins words and absolute-value bars denote word length. A plane tree is a subset of this countable address set containing the empty word, closed under prefixes, and having at each retained address precisely an initial finite list of ordered children:

\[ u\in T\ \Longrightarrow\ \exists k_T(u)\in\mathbb N_0:\quad uj\in T\ \Longleftrightarrow\ 1\le j\le k_T(u). \]

Identify subsets with binary indicator families and use the countable product Borel σ-algebra. The root condition is a cylinder event; prefix closure is a countable family of implications; the child condition is a countable union of countable intersections for each address. Locally finite plane trees therefore form a measurable subspace. Each generation is finite by induction from the root. Finite trees form a countable subspace, since a countable set has only countably many finite subsets; every map from it into a countable space is measurable. For complete infinite trees see [T-GW-TREES](t-gw-trees.md#gw-tree-space).

Ancestry is the prefix relation. The longest common prefix of two words is their most recent common ancestor. To move between the words one must delete letters back to that prefix, then append the remaining target letters. This is the unique path without repeated edges, so the graph distance is

\[ d_T(u,v)=|u|+|v|-2|u\wedge v|,\qquad T_u=\{w:uw\in T\}. \]

The second expression defines the descendant subtree after stripping its prefix. Plane order is additional retained structure: forgetting sibling order can identify distinct address trees. Counts of plane trees are therefore not automatically counts of unordered trees.

## 2. Pending slots and the Łukasiewicz bijection

<a id="coding-lukas"></a>

List a finite tree by visiting a parent first, then each child subtree completely in sibling order. Write its number of vertices as n and start the list at index zero. With the successive offspring counts denoted below by k, define

\[ v_0=\varnothing,\ldots,v_{n-1},\quad k_j=k_T(v_j),\quad S_0=0,\quad S_{j+1}=S_j+k_j-1. \]

Maintain an ordered list of pending addresses, initially containing only the root. At each step remove its first item and insert that vertex’s children at the front in order. Its length changes by the offspring count minus one, so before each visit it equals one plus the path value. It is nonempty until exploration ends and empty afterwards. Hence

\[ S_{j+1}-S_j\in\{-1,0,1,\ldots\},\quad S_j\ge0\ (0\le j<n),\quad S_n=-1. \]

Conversely, take an integer path satisfying these conditions, use each increment plus one as an offspring count, and run the same list algorithm. Inductively the list length before a step is one plus the path value, so no step encounters an empty list prematurely. At the end it is empty, leaving no unrealized children. Every new address has a unique parent and consecutive sibling labels, giving a plane tree with exactly n vertices. Front insertion completes the current subtree before the next sibling, so the order is preorder. Offspring counts determine the algorithm uniquely at each step, proving both injectivity and surjectivity. Total offspring is the number of vertices minus one, the number of edges. For n equal to one the path consists of a single step from zero to minus one.

## 3. Subtree first descent and the weak-record height formula

<a id="coding-height"></a>

\[ r_i=\inf\{j>i:S_j=S_i-1\},\qquad 0\le i<n. \]

Starting just before this vertex is visited, track only pending slots generated by its subtree. There is initially one. Until that subtree is exhausted, the front of the list lies in it, and its pending count is one plus the path change from the starting level. A downward step is at most one, so the first zero occurs exactly at the stated first descent. Finiteness guarantees this occurs. The subtree thus occupies consecutive indices from i to just before that descent. A later vertex is in the subtree exactly when the path has not fallen below the starting level between the two indices.

\[ v_i\preceq v_j\ (i<j)\ \Longleftrightarrow\ S_i=\min_{i\le k\le j}S_k,\qquad |T_{v_i}|=r_i-i. \]

Height is the number of strict ancestors. Summing this equivalence over earlier vertices gives the full path-to-height conversion:

\[ H_j=|v_j|=\sum_{i=0}^{j-1}\mathbf1\!\left\{S_i=\min_{i\le k\le j}S_k\right\}. \]

These are weak records: ties cannot be discarded. Fix the endpoint and read backwards, taking the endpoint value minus an earlier value. The formula asks that this reversed value attain its running maximum, allowing ties. Along a chain of single-child vertices the path stays zero until the final leaf, while heights keep increasing. Strict records would miss all these ancestors.

## 4. Recovering every parent from heights alone

<a id="coding-height-inverse"></a>

\[ H_0=0,\qquad 1\le H_j\le H_{j-1}+1\quad(1\le j<n). \]

Theorem: a finite integer sequence is the preorder height sequence of a unique plane tree if and only if it satisfies these conditions. Necessity follows from the next preorder visit: it either visits the current vertex’s first child, increasing depth by one, or returns to an ancestor before entering an unvisited child. The root is listed once, so every subsequent height is at least one.

For sufficiency use an active ancestor stack, initially containing the root. On reading a new height, remove all stack vertices whose depths are at least that height. The upper bound ensures that the stack previously reached the new height minus one; the lower bound leaves the root. The remaining final vertex is therefore the parent. Append the new vertex as its next child and push it onto the stack. A popped vertex never receives further children, so this list is indeed the resulting tree’s preorder. The parent must be the most recent earlier vertex at height one less. Every realization must make that connection, proving uniqueness.

Thus the height sequence does not explicitly list offspring counts but still retains genealogy. Removing its order and retaining only how often each height occurs leaves generation sizes and destroys the bijection.

## 5. Contours, Dyck paths, and their inverse algorithm

<a id="coding-contour"></a>

\[ C_0=C_{2(n-1)}=0,\qquad C_\ell\ge0,\qquad C_{\ell+1}-C_\ell\in\{-1,1\}. \]

Start at the root, walk down each edge at unit speed to the next child, and return along the same edge after finishing its subtree. Each edge is traversed exactly twice, so duration is twice the number of edges. Record distance to the root at integer times and interpolate linearly. For n equal to one the domain consists only of time zero. This gives the displayed nonnegative Dyck path.

The inverse algorithm maintains the ancestor stack. Each up-step creates a new child of the current vertex, labeled in creation order, and pushes it onto the stack. Each down-step pops its last vertex. Nonnegativity prevents a descent from the root; the zero endpoint returns from every created edge. Up-steps and down-steps each number one less than the vertex count. The return along each edge occurs exactly when its subtree has finished, so the constructed contour is the given path. Each up-step must create a new child rather than choose an old one; otherwise the height path would no longer describe the stipulated contour traversal. This proves another bijection.

## 6. Two clocks and the most recent common ancestor

<a id="coding-clocks-distance"></a>

\[ b_j=2j-H_j,\qquad C_{b_j}=H_j,\qquad 0\le j<n. \]

Before the first arrival at the jth nonroot vertex, j edges have been created, hence j up-steps have occurred. Current depth is up-steps minus down-steps, so the number of down-steps is j minus that depth. Their sum gives the first-visit time formula. Consecutive first-visit times differ by the previous height minus the next height plus two, at least one. Between them the contour descends to the next height minus one, then makes one up-step. After the last first visit it descends to the root. Thus heights determine all these times and the entire contour. Conversely, recording heights at the new vertices created by contour up-steps recovers the sequence.

\[ d_T(v_i,v_j)=H_i+H_j-2\min_{b_i\le t\le b_j}C_t\qquad(i\le j). \]

If the earlier vertex is an ancestor of the later one, the contour between their visits stays in its subtree and has its minimum there. Otherwise it returns from the earlier child subtree to the most recent common ancestor, then enters the child subtree containing the later vertex. Preorder prevents it from moving above that ancestor in between. Its minimum is therefore exactly the ancestor’s depth, and the address distance gives the formula. Linear interpolation does not change the minimum, attained at an integer time.

\[ |v_i\wedge v_j|=\min_{i<k\le j}H_k-1\qquad(i<j). \]

The latter minimum excludes the earlier index. Between these first visits there is a child of the common ancestor, while all other listed vertices lie in one of its child subtrees. The smallest height is therefore that ancestor’s depth plus one. Including both endpoints and forgetting the subtraction gives a wrong answer: two consecutively visited sibling leaves can both have height two, but their common ancestor has depth one. This chapter recovers the whole discrete plane tree with unit edge lengths; continuous-function quotient spaces and their limits do not follow automatically.
